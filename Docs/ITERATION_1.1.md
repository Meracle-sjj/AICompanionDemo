# 1.0 异机首次试玩 → 1.1 迭代预期

记录日期：2026-10-10（北京时间）。来源：作者在实验室 Windows 电脑的首次试玩反馈。作者确认安装运行库后可顺利进入游戏，运行流畅；这不是规模化玩家测试、性能基准或完整通关验收。

**本记录发布时尚未实施本轮游戏代码改动。** 1.0 下载保留，1.1 为本轮开发目标，尚无已完成的新版本包。

## 目标与预期

降低首次运行和测试入口的操作成本，缓解开局对特定强力技能的依赖，恢复队友稳定移动，让后期成长分工与事件信息更容易理解。下面先记录用户观察和预期，诊断假设不当成已经证明的原因。

## 公开记录协议

1. **先发表预期，再实施。** 每批代码前在 GitHub 留下触发问题、目标、方案与验收条件；本 issue 是本轮先行预期。需要调整设计时先追加决策记录，再落代码。
2. **分模块留存。** 实施期间按实际进展推送源码与进度，提交说明链接到本 issue；不覆盖或重写 1.0 发布历史，不把工作中状态描述为完整实装。
3. **区分四个状态。** “计划中”尚未落代码；“已实装”已接到真实运行入口；“已验证”有实际构建/运行或作者复验记录；“已发布”附件已上传并核对可下载。调查与许可/证书限制单独说明。
4. **完成再宣布。** 本轮功能模块完成后逐项公布实现、验证和待验范围，再发布整体完成说明。仍有未完成模块时保留未完成状态；不以代码存在、编译成功或自述代替体验验收。
5. **形成面试证据。** 用“问题 → 分析 → 设计判断 → 实现 → 验证 → 后续反馈”的链条，明确作者负责体验目标、裁决与实玩反馈，AI 辅助实现。没有统计来源的改善不写百分比或玩家数据。
