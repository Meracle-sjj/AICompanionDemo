# 110秒求职演示分镜

这是一份待录制的90–120秒演示脚本，目标时长110秒；尚未生成视频或完成剪辑。材料核对日期为2026-10-10。当前独立Win64候选已显示开始界面，核心交互的独立包验收仍待完成；原开发工程已有作者试玩与专项证据。最终包状态、体积和启动结果以[发布记录](RELEASE.md)为准，不能把历史PIE验收写成这次独立包实测。

## 分镜与旁白

| 时间 | 待录画面／现成材料 | 旁白建议 | 这段要证明什么 |
| --- | --- | --- | --- |
| 0–8秒 | 最终候选真实标题页，随后进入正常局；字幕「个人系统策划作品 · UE5.6.1 / C++」 | 「这是一个与AI队友协作的生存原型。我把自动输出后的主动决策，放在站位、队友模式和局内构筑上。」 | 作品定位与核心问题。开始界面已观察到，进入局内画面仍需录制核验。 |
| 8–23秒 | 同一场战斗中按Q切换护卫／歼灭，保留HUD模式名；分别拍跟随玩家与追击目标 | 「护卫保持队形，歼灭允许追击。玩家决定保护与输出的取舍；两种模式共享选敌和火力，移动策略与被动不同。」 | 模式是玩家决策，画面能看见行为差异。10%数值用字幕补充，不用无对照片段声称已测倍率。 |
| 23–43秒 | 6秒[核心循环图](diagrams/01-core-loop.png)，接升级三选一、宝箱或风险祭坛提示的真实录屏 | 「经验、金币和探索接入同一成长循环。递增箱价与风险祭坛提供资源取舍，Boss挑战再给专属遗物。玩家六级解锁自动射击。」 | 成长入口与机会成本。Boss祭坛3／6／9分钟、狂暴12分钟用规则图表达；无需伪装成110秒内自然发生。 |
| 43–61秒 | [协作AI图](diagrams/02-companion-ai.png)局部放大；配一段玩家受击后队友选敌的真实画面，必要时附同期日志 | 「选敌不是只挑最近。视觉和玩家受击来源共同提供候选，距离、威胁与残血评分，再用切换和视线惩罚约束转火。信息缺失先修输入链。」 | 设计判断与实现对应。0.3／0.6／0.1是默认权重，不是命中率或保护成功率。 |
| 61–82秒 | 真实召唤师单发火球片段；插入[反馈迭代图](diagrams/03-feedback-iteration.png)。若通过测试模式召Boss，全程保留「测试模式 · 机制展示」角标 | 「试玩发现火球从头顶飞过仍扣血。旧版XY判定忽略高度和地形；修订让35厘米可见核心与连续球扫一致，按首次接触结算，地形同距优先。」 | 从体验问题推导几何约束。图是规则示意；历史高空误伤复现与作者确认范围见[证据索引](EVIDENCE.md)，不剪成尚未录得的前后实测对照。 |
| 82–98秒 | 将反馈、规则修订、源码与验收四步并列；可以选现有证据摘要及对应源码，保持文字可读 | 「我负责体验目标、规则裁决、方向、试玩反馈和最终验收，AI辅助实现。项目里运行的是离线FSM与Utility AI。已有作者试玩和专项记录，完整发布验收另列。」 | 本人职责、AI辅助边界与事实纪律。没有团队规模、留存或A/B数据。 |
| 98–110秒 | 最终版本真实局内定帧，叠作品名与「操作指南／发布记录／源码」；下载入口录制时按实际发布地址填写 | 「试玩入口和操作说明在README。系统关系、源码入口和验证范围也保留在文档里，方便继续核对。」 | 让招聘方知道怎样继续体验与审阅。此处不预填不存在的远端下载链接。 |

## 录制前需补的实证

| 镜头 | 取得方式与条件 |
| --- | --- |
| 正常局、Q切换、升级与资源提示 | 先完成该候选的独立包核心交互验收，再从真实操作录制；保留HUD与版本记录。 |
| Boss与协作效果 | 自然局取到则注明实际局内时间；使用测试模式直加技能或召Boss，保留角标，不能当作自然构筑、平衡或通关证据。 |
| 评分板 | 默认关闭的`bEnableScoreboard`需显式开启；当前游戏源码未核得F1开启绑定。没有实际评分录屏时使用机制图与源代码，不预设玩家快捷键。 |
| 最终试玩Shot | **待发布负责人提供最终候选的真实局内截图。**收到后补版本、正常／测试模式、场景说明和相对路径；目前没有图片占位链接。 |

每段录制至少留前后各两秒原素材。需要跳过等待或拼接不同局时显示「节选／时间跳转」；测试模式可用于解释规则，结束页只有实际进入后才能展示。建议1080p、中文字幕和游戏音量压低，BGM是否存在与素材授权边界按[第三方说明](THIRD_PARTY.md)及实际候选处理。导出后实看一遍，确认字幕、HUD与图中文字可读、总长在90–120秒内，文档不得先写“视频完成”。
